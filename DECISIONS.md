# Decisions

- **Pose held = key held, no tap mode.** WoW's GCD/cooldowns already rate-limit repeats. Jump is a held pose too; it only lasts while the hips are rising.
- **Poses are feature rules, not recorded templates.** Each pose = conditions on named body features (arm raise angle, hip rise, step cadence…), tuned in the web GUI with live values. Template matching was tried first and dropped: user stands far from camera, so raw-landmark distance was too noisy and untunable.
- **Features in torso-length units or degrees, 13 body joints, xy only.** Invariant to camera distance and body size. Face/finger landmarks dropped as noise. z dropped: MediaPipe depth is unreliable from one camera.
- **Web GUI over native.** User is metres from the laptop; a browser tab with big text is readable, and the capture/trace tooling is cheap in HTML.
- **MediaPipe Tasks API, lite model.** mediapipe 1.x removed the legacy `solutions` API. Lite runs ~30fps on CPU; swap to `full`/`heavy` model file if accuracy is lacking.
- **Detect on the unmirrored frame, mirror the landmarks after.** The preview is mirrored like a bathroom mirror, but MediaPipe is trained on unmirrored images and labels a mirrored person's right side as LEFT. Un-flipping before detection makes `left_*` features the user's real left; x is then mirrored back so the overlay and stick figures match the preview.
- **pynput for keys.** OS-level events, same as a real keyboard. Needs Accessibility permission on macOS.
- **Camera backend forced to AVFoundation on macOS.** CAP_ANY picks FFmpeg first and fails to enumerate devices.
- **Packaged as its own app (PyInstaller) so Accessibility is granted to `Movement.app` alone**, not to Terminal or VS Code and everything they spawn. Per-OS build (`python build.py`); PyInstaller cannot cross-compile, so Windows builds on Windows.
- **Packaged config lives in the user data dir** (`~/Library/Application Support/Movement`, `%APPDATA%\Movement`), not inside the bundle. Bundles are read-only and replaced on rebuild. Dev runs keep `config.yaml` in the repo root.
- **App prompts for Accessibility on launch when packaged.** That is the only way macOS adds the app to the Accessibility list; otherwise the user has to find it by hand.
- **Built-in presets are read-only; users build on top.** Shipped `presets.yaml` can't be edited from the packaged app (server ignores changes to it), so a user can't break them; their own presets and groups live in `my_presets.yaml`. Running from source they're editable, since that's how untested built-ins get tuned before shipping. Loading repairs name clashes and dangling group members when a new build changes the built-ins.
- **Keys belong to groups, not just presets.** A preset has a default key; a group (a game or class setup) overrides it per pose, because the same jump is space in WoW and x in Mario. So keys aren't part of the tuning a pose card saves back to its preset.
- **Send keys is session-only.** Never saved to `config.yaml` or exported, and dropped from an older config or an import, so every launch starts with keys off: a saved "on" would send keys into whatever window has focus as soon as a body is seen.
- **Held or repped is the routine's choice, not the pose's.** A pose's conditions are its end position, so the same squat is a held squat or a squat rep (each time it turns on). Only poses that need motion (jump, jog, punch) can't be held. Drill settings choose for now; per-step targets in groups ("chair 30s", "squat ×10") come later. Keys are unchanged: a pose still holds its key while on.
